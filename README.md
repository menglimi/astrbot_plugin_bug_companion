# 我会陪你修 Bug

> **群聊通知（2026-10-11）：** 原群聊被停用一周，期间可先加入 bot 群：**145326153**。

“我会陪你修 Bug”是一个面向 AstrBot 开发者交流群的问题治理插件。它收集和整理 Bug、使用问题与优化建议，交由人工审批后追踪待办、沉淀已确认知识，并可定期读取 GitHub 仓库，把新提交和版本发布播报到指定群聊。

## 功能

- 只观察配置或页面启用的群聊，不拦截普通聊天；完整 UMO 只会精确匹配对应平台会话。
- 将连续群消息作为上下文批量交给模型；模型只负责初审票拟、事实整理和待办建议，不替用户完成最终审批。问题归属区分插件、AstrBot、模型和其他问题，知识分类独立记录当前已知 Bug、历史已修复 Bug、FAQ、兼容问题、优化建议和待确认反馈。
- 支持通过 NapCat / SnowLuma 的 OneBot 历史接口直接读取真实 QQ 群记录；不会使用其他插件缓存，也不会尝试裸读 QQ 加密数据库。
- 原始证据、问题状态、相似关系、人工编辑和答疑结果全部进入 SQLite，并保留审计记录。
- 指定群聊按静默窗口持续采集，模型先预标记可能的问题，再结合连续对话校对真实性、解决状态与方案证据。
- 新候选依次进入“御案”人工审批，可设为待办、驳回无用记录、认可问题与方案或先修改方案；最后一项待办办结后会自动重呈审批，所有动作保留审计。
- “设为待办”提供“后续版本优化、等待上游修复、补充文档说明、补充证据后再定”等处置方案预设；预设只填充待办预案，可继续修改，不会直接进入知识库。
- 只有人工认可且满足验证条件的解决方案才进入知识库并参与自然答疑；也支持 `/修bug 答疑 <问题>`。
- 支持定期读取 GitHub 仓库；首次启用只建立当前提交/版本基线，后续将新增动态合并成一条消息，发送到单独配置的固定群 UMO，不会自动复用问题收集群。
- 仓库动态可选用已配置的整理模型生成本轮变更摘要；模型不可用或摘要失败时，会自动保留原始提交与版本列表发送。
- 拓展页提供御案、待办册、案牍库、收奏箱、答疑录、群辖、设置、合并、封存和 JSON 导出。这里的“入典”表示发布为可检索知识，“封存”表示保留证据但退出正常检索与答疑。

## 快速开始

1. 在插件配置的“群聊收集”中填写完整 UMO 或群号，或在目标群使用管理员命令 `/修bug 启用当前群`。
2. 在插件配置或“修Bug工作台”的模型设置中填写要管理的插件名称，每行一个；模型只有在证据明确时才会从该名单选择具体插件，无法判断时保留“未指定插件”。
3. 在 AstrBot 拓展页打开“修 Bug 奏事台”，在御案中逐条审批模型票拟；未解决的问题设为待办，方案完整后再认可归档。
4. 根据需要选择整理模型；整理模型和备用模型都留空时才会使用当前会话模型。只要显式选择了任一整理模型，失败后也不会把群聊证据转交给当前会话模型。
5. 在工作台“设置 / 仓库动态”中打开推送，填写 GitHub 仓库地址和固定群的完整 UMO；可分别选择提交、版本发布、AI 摘要、检查间隔和每仓库每类展示上限。

公开仓库可直接匿名读取；仓库较多或需要读取私有仓库时，可在 AstrBot 运行环境中设置 `GITHUB_TOKEN`。令牌只作为 GitHub API 请求头使用，不会写入插件数据库或群消息。

常用命令：

- `/修bug 提交 <问题描述>`：手动提交一条问题。
- `/修bug 答疑 <现象或问题>`：检索已解决记录并生成答复。
- `/修bug 状态`、`/修bug 列表`、`/修bug 帮助`。
- 管理员可使用 `/修bug 启用当前群`、`/修bug 停用当前群`、`/修bug 重新整理`。
- 管理员可使用 `/修bug 导入群历史 [天数] [上限] [暂存|整理]`。默认只在本地暂存并标记来源，重载或后续新消息也不会把它自动交给模型；显式选择“整理”、使用“重新整理”命令或在工作台确认整理后才会进入模型队列。

`提交`、`答疑`、`状态` 和 `列表` 只会在已启用的开发者交流群中读取或写入数据。页面或命令对群的显式停用优先于配置列表，避免配置变更或后续消息意外重新开启收集。

数据默认保存于 `data/plugin_data/astrbot_plugin_bug_companion/bug_companion.sqlite3`。QQ 历史导入归档只记录本次新增的规范化消息，不再复制协议端完整原始结构；工作台维护会按“原始消息保留天数”同步清理过期归档，`0` 表示永久保留。插件不会把模型异常文本发送到群聊；整理失败的原始消息会留在“待整理”中等待重试。
